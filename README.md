# LinkDesk

一套键鼠，连接 Mac 与 Windows。当前 Windows **0.4.3 修复构建验证中**，Mac **0.4.2 独立版**，Mac 使用 SwiftUI，Windows 使用 WPF。两端内置 Deskflow 1.27.0 连接核心与必要运行库，无需另装 Deskflow；Windows 无需另装 .NET。

## 下载与连接

0.4.2 修复源码见 [源码发布页](https://github.com/vvanjune/LinkDesk/releases/tag/v0.4.2)。双端完整安装包已构建和校验，但 GitHub 大文件上传多次超时，当前发布页暂不提供 0.4.2 安装包。此前的完整包及未改动的上游源码资料见 [v0.4.0 发布页](https://github.com/vvanjune/LinkDesk/releases/tag/v0.4.0)；旧版安装包仍有本次已修复的用途缓存问题。

这是测试发布，Mac 使用本地签名、尚未公证，Windows 尚未进行发布签名。支持 Apple Silicon Mac 与 Windows x64。

1. Mac 将完整 LinkDesk.app 放入应用程序，允许设备控制；Windows 完整解压后运行 LinkDesk.exe，保留 core 和 ThirdParty 文件夹。
2. 两台电脑连接可互通的局域网，一端选择共享键鼠、另一端选择接收。
3. 两端在“配对设备”明确选择对方，核对完整指纹并确认，然后启动共享。

详见 [使用说明](使用说明.md)。Mac → Windows、Windows → Mac、Mac → Mac、Windows → Windows 均有共享与接收实现。可使用路由器、热点、有线局域网，不限定 Windows 开热点。四种组合的配置测试通过；各组合硬件验证情况见 [验证记录](验证记录.md)。

## 多设备配对

- 同名电脑按不同 SHA-256 指纹分别列出，支持备注名称、选择、忘记和手动添加。
- 可以保存多台配对设备，每次选择一台连接；当前连接的信任范围只包含所选指纹。
- 双端签名发现验证所选身份后更新地址；其它已配对设备不会替换当前选择。
- 平台、用途、名字、地址为签名元数据；配对身份由完整指纹确认，发现本身不会自动授予信任。
- 按键映射与滚动设置分别随设备保存。升级保留身份和设置，多份旧配对需明确选择。

这不是同时连接多台的屏幕网格。发现限于同一 IPv4 局域网；广播被阻挡时可以手动添加，网络仍须互通。未提供公网穿透或 USB 鼠标模拟。

## 0.4.2 用途切换修复

切换用途后，旧设备公告曾让两端被错误判定为用途相同，导致不能启动或连接被停止。现在保存和启动都会刷新公告；缓存用途用于显示，不再阻断所选身份的连接。完整指纹校验与所选设备的独立 TLS 信任范围不变。

Swift、C# 回归检查通过，双端构建与 Mac 签名检查通过。0.4.2 更新后的实机验证另行记录。Windows 0.4.3 正在验证启动和显示保护修复，尚不能宣称通过实际显卡黑屏验收。Mac 接收端光标暂时不可见仍未确认根因；见 [排查记录](排查记录.md)。

## 日常使用

Windows 0.4.3 将“登录后打开应用”和“启动后开始共享”分开；升级后默认关闭自动开始共享和主动唤醒显示器。网络恢复合并 10 秒内的连续变化，正常进程在唤醒后保留，异常进程暂停自动恢复。手动停止后保持停止。关闭窗口可留在后台。按键映射在共享端设置，远程滚动方向和速度在接收端设置，不改本机输入或 Mos。没有新增切换快捷键。

## 开发与许可

源码在 source；构建需要 Swift 工具链或 .NET 10 SDK、Python 3，以及官方 Deskflow 1.27.0 二进制发行包作为嵌入输入。构建依赖不会成为用户的外部安装依赖。Windows 0.4.3 还需由固定版本上游源码和公开补丁构建的核心，打包程序拒绝回退到旧核心。步骤与测试见 [技术说明](source/README.md)。

LinkDesk 源码采用 [GPL-2.0-only](LICENSE)。传输核心来自 [Deskflow](https://github.com/deskflow/deskflow)，Windows 0.4.3 对显示唤醒与本地保活接口做了可审查的补丁，Mac 核心保持原版。上游许可和运行库声明见 [third-party](source/third-party/README.md)，对应上游源码与安装包一同发布。
